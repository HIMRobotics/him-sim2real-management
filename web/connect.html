BEFORE YOUR FIRST RUN

Start with the computer
that already sees the G1.

This app manages recording sessions. The robot operators still manage power, motion modes, policies and emergency stopping.

1. Choose the right setup

Mac/Linux laptop: open the app locally and choose Set up the G1 over SSH. Enter the known SSH destination and SDK Python, then Check SSH access → Copy recorder to G1 → Open robot recorder. The buttons run the setup commands and open the tunnel. You can also transfer a policy file; it is verified but never executed.

Guided setup needs an already trusted SSH host and an unlocked key/agent. It cannot handle password prompts or install the Unitree SDK. Follow the first-time login help in the app if needed.

Linux control laptop: run the app in the same environment that already receives the G1’s Unitree SDK data. Open the browser on that laptop.

SDK on the G1/onboard Linux: run the app there and view it from your laptop through SSH. A Mac or Windows browser works this way; native Windows execution of the recorder is not supported.

The browser itself does not connect to robot hardware. The Python recorder does. It needs Python 3.9+ and the existing Unitree SDK2/Cyclone DDS installation.

2. Choose connection settings

Use the operators’ existing robot cable/network configuration. Select the actual robot-facing interface in Connection settings. Keep domain 0 unless they configured another DDS domain. If necessary, enter the full path to the Python interpreter that already has the SDK.

Click Check connection. Continue only after Connected. Live G1 state received. A failed check cannot enable recording.

No IP addresses, credentials, firmware or network settings are guessed or changed. Confirm the selected network reaches the intended G1, not a simulator or another robot.

3. Make one short stationary recording

With the operators holding the robot in its normal safe stationary state, record 15–30 seconds. Require a growing state count, then stop and open the report. Check for nonzero data and no unexplained gaps/errors. Prepare and download a return ZIP.

This checks the real connection, recording and export on their computer. The release’s own tests used synthetic data; they do not prove physical G1 compatibility.

4. Manage each policy session

Start recording → wait for RECORDING → launch the policy normally → stop the policy normally → stop recording → add outcomes/files → Prepare data for Arena → download the ZIP.

Use a separate run for each policy. Keep failed attempts. The app never launches a policy, sends motor commands, takes the camera, or uploads to Arena automatically.

Viewing an onboard recorder through SSH

From your laptop, use the operators’ real username and G1 computer address:

ssh -L 8765:127.0.0.1:8765 YOUR_USER@YOUR_G1_COMPUTER

In that SSH terminal, go to the kit folder and run:

PYTHON=/path/to/existing/sdk/python bash OPEN_APP.sh --no-browser --port 8765

Open the full printed localhost link, including its access key, on the laptop. Keep SSH open. If the app prints a different port, forward that actual port. Do not expose the app publicly.

Detailed instructions are in CONNECTION_GUIDE.md and TROUBLESHOOTING.md in the kit. Unitree’s official SDK setup. Do not run a motor-control example just to check telemetry.
